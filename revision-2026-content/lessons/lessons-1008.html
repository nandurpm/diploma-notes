Concept handbook

Computer architecture and the data path

Input devices create data; CPU control unit and ALU process instructions; RAM holds active work; storage preserves files; output devices communicate results. Firmware starts hardware and the operating system manages resources.

CPU, RAM, HDD and SSD

Processor model or clock does not alone determine performance. RAM capacity affects active workload. HDD offers magnetic storage with moving parts; SSD offers flash storage and usually lower latency.

Ports and peripherals

USB carries data and sometimes power; HDMI/DisplayPort carry digital audio/video; VGA is analog video; RJ45 Ethernet supports wired networking; audio jacks, webcams and external drives are peripherals.

System software versus application software

Operating systems, device drivers and utilities are system software. Word processors, spreadsheets, browsers, presentation tools and CAD packages are application software.

Linux GUI file operations

Create, rename, move, copy, search and delete using a file manager. Use a predictable directory tree, clear filenames, versions and backups.

Advanced search and source verification

Combine exact phrases, site:, filetype: and minus operators. Verify authority, date, scope, file type and consistency with another reliable source.

Email fields and netiquette

To is the primary action recipient; CC keeps stakeholders informed; BCC protects recipient privacy. Use a specific subject, concise body, signature and attachment check.

LMS and connectivity

Enroll with the correct identity, read announcements, submit the right file format and confirm submission status. Protect credentials and use secure networks.

Computer system data path

Observe the difference between temporary working memory and persistent storage.

Experiment 1

Hardware & Software Exploration

2 instructional hours · CO1 · Remember

Official practical outcome: Identify the CPU, RAM, HDD/SSD and peripheral ports; identify application software and system software on a personal computer.

Aim

Identify major computer hardware, peripheral ports, system software and application software without damaging the equipment.

Apparatus / software

Laboratory PC, hardware demo kit, ESD wrist strap when available, port-identification sheet, operating-system system-information utility.

Underlying theory

A computer system combines hardware, firmware and software. CPU executes instructions; RAM is volatile working memory; HDD/SSD provide non-volatile storage. Ports provide physical interfaces, while the operating system, drivers and utilities manage hardware resources.

Safety, privacy and quality

Shut down and isolate power before opening a cabinet. Do not touch exposed contacts. Use ESD precautions and faculty supervision for disassembled components.

Procedure
  1. Record PC make/model and operating system.
  2. Open the system-information tool and note processor, installed RAM and storage.
  3. Identify motherboard, CPU location, RAM module, HDD/SSD and SMPS from the demo kit.
  4. Identify USB-A, USB-C, HDMI, VGA/DisplayPort, audio, Ethernet and power ports.
  5. List at least five system software items and five application software items.
  6. Classify each item and obtain faculty verification.

Observation / evidence

Create a table with columns: Item/Port, category, visual identifier, function, evidence or specification.

Result

Major hardware, ports, system software and application software are identified and correctly classified.

Possible errors and troubleshooting
  • Confusing RAM capacity with storage capacity.
  • Calling every program “software” without classifying it.
  • Handling components while the system is powered.
Viva questions with answers
Why is RAM called volatile memory?

Its contents are lost when power is removed.

HDD and SSD differ mainly in what way?

HDD uses moving magnetic parts; SSD uses semiconductor flash and normally has lower access time.

What is a device driver?

System software that lets the operating system communicate with specific hardware.

Experiment 2

File and Folder Management in a Linux GUI

2 instructional hours · CO1 · Understand

Official practical outcome: Create folders and files in Linux using a Graphical User Interface (GUI).

Aim

Create, rename, move, copy and delete files and folders using a Linux desktop file manager.

Apparatus / software

Ubuntu LTS or another institution-approved Linux GUI, file manager, text editor.

Underlying theory

A directory tree organizes data hierarchically. Absolute paths begin at the root; relative paths are interpreted from the current location. Copy produces another item, while move changes location or name.

Safety, privacy and quality

Work only inside the assigned student folder. Do not delete system folders or another student’s files. Confirm the target before permanent deletion.

Procedure
  1. Create a semester folder using a clear name.
  2. Inside it, create one folder per subject code and module subfolders.
  3. Create the prescribed Backpack folder with Food and Tools subfolders.
  4. Inside Tools create flashlight.txt and map.txt.
  5. Move map.txt to Food; copy flashlight.txt as spare_light.txt.
  6. Delete Food and its contents, then list the remaining Backpack items.
  7. Capture a screenshot or record the final tree.

Observation / evidence

Record each operation, source path, destination path and final status. The final Backpack should contain Tools with flashlight.txt and spare_light.txt.

Result

The required Linux GUI directory tree is created and verified.

Possible errors and troubleshooting
  • Using ambiguous filenames such as final2-new.
  • Moving when a copy was required.
  • Deleting the parent folder instead of the selected subfolder.
Viva questions with answers
What is the difference between copy and move?

Copy creates another instance; move relocates the original.

What is a file extension?

A suffix that commonly indicates file type, such as .txt or .pdf.

Why use subject codes as folder names?

They produce a consistent, searchable structure linked to the curriculum.

Concept handbook

Document styles and table of contents

Use Heading 1/2 and body styles; modify the style definition once instead of formatting each heading. Insert captions, page numbers and an automatic TOC, then update fields before PDF export.

Professional biodata layout

Use a two-column borderless table for aligned labels and values. Maintain whitespace, concise evidence-based skills and only necessary personal details.

Spreadsheet data discipline

One header row, one record per row, one variable per column, consistent data types and no decorative blank rows inside the dataset.

Cell references

Relative A1 changes when copied; absolute $A$1 is fixed; mixed $A1 or A$1 locks one dimension. Use references rather than retyping constants.

Core functions

SUM totals numbers; AVERAGE gives arithmetic mean; COUNT counts numeric cells; COUNTA counts non-empty cells; COUNTIF counts matching records; IF returns one of two outputs.

Presentation planning

Define audience, purpose and call to action before designing. Use one message per slide and evidence rather than decoration.

Slide Master, transitions and animations

Slide Master controls repeated elements. Use transitions between slides and animations within slides only when they clarify sequence or emphasis.

Cloud permissions and version history

Choose Viewer, Commenter or Editor. Use comments/suggestions for review and version history to identify or restore edits.

Optional Overleaf/LaTeX

LaTeX source is compiled into PDF. A minimal document includes document class, begin/end document, title, list and math syntax.

Cell-reference behaviour

B2 changes when filled down; $F$2 remains fixed.

Email recipient logic

BCC is the privacy control in the official announcement scenario.

Experiment 5

Spreadsheet Basics

2 instructional hours · CO2 · Apply

Official practical outcome: Use formulas SUM, AVG/AVERAGE, COUNT, COUNTIF and IF, with cell referencing.

Aim

Create and verify spreadsheet formulas for pass counting, cricket statistics and selection status.

Apparatus / software

Microsoft Excel, LibreOffice Calc, Google Sheets or approved equivalent.

Underlying theory

A formula begins with = and uses cell references. Relative references change when copied; absolute references such as $F$1 remain fixed. COUNT counts numeric cells, whereas COUNTA counts non-empty cells.

Safety, privacy and quality

Do not overwrite source data. Keep an unmodified copy and avoid enabling untrusted macros.

Procedure
  1. Enter a clean table with one header row.
  2. Use =SUM(B2:B21) and =AVERAGE(B2:B21) for runs.
  3. Use =COUNTIF(C2:C21,"Batsman") for category count.
  4. Use =IF(B2>=50,"Selected","Waitlist") and fill down.
  5. Use COUNT on a numeric participant field; explain why COUNT on text names may return zero and use COUNTA when counting names.
  6. Check formulas with sample manual calculations and save the file.

Observation / evidence

Record formulas, returned values, copied ranges and manual verification.

Result

Spreadsheet functions and cell references are applied and verified.

Possible errors and troubleshooting
  • Using COUNT on a text-only Player Name column and expecting the participant total.
  • Omitting quotation marks around text criteria.
  • Including the header cell in a numeric range.
Viva questions with answers
COUNT and COUNTA differ how?

COUNT counts numeric cells; COUNTA counts non-empty cells.

What does $A$1 mean?

Both column and row are absolute when copied.

What happens when an IF condition is false?

The value_if_false argument is returned.

Concept handbook

Preparing data for analysis

Remove merged cells, fix headers, standardize categories and make numbers numeric. Document missing values rather than hiding them.

PivotTable fields

Rows and Columns group categories; Values aggregate; Filters and slicers restrict the view. Always check whether the aggregation is Sum, Count, Average or another function.

Slicer behavior

A slicer changes the visible subset and therefore totals. It does not delete source records. Clear the filter to return to the full dataset.

Refresh and source range

When new rows are added, refresh. If the source is not a dynamic table, extend the source range before refreshing.

Chart selection

Bar/column: category comparison. Line: ordered time trend. Pie: small part-to-whole composition. Scatter: relationship between two numeric variables.

Honest visualization

Use clear titles, units and readable labels. Avoid misleading axes, unnecessary 3D effects, excessive colors and hidden categories.

AI slide workflow

Specify audience, objective, structure, slide count, tone and evidence constraints. Generate, fact-check, edit, cite and present.

AI-assisted current information

The assistant explains at the learner’s level, asks a checkpoint question, waits, gives feedback, adapts difficulty and states uncertainty.

Solved Examples and Demonstrations

Complete working, not unexplained answers

1. Cricket selection formula

  1. Given: Runs in B2 = 62; cut-off = 50.
  2. Required: Selection Status.
  3. Formula: =IF(B2>=50,"Selected","Waitlist")
  4. Test: 62 >= 50 is TRUE.
  5. Final output: Selected.
  6. Verification: Change B2 to 49; output must become Waitlist.

2. COUNT versus COUNTA

  1. Given: A2:A21 contains 20 player names.
  2. Incorrect assumption: =COUNT(A2:A21) gives 20.
  3. Reason: COUNT ignores text.
  4. Correct formula: =COUNTA(A2:A21)
  5. Final output: 20, provided no blanks exist.

3. Pass/fail summary

  1. Status formula: =IF(B2>=40,"Passed","Failed").
  2. Passed count: =COUNTIF(C2:C31,"Passed").
  3. Failed count: =COUNTIF(C2:C31,"Failed").
  4. Check: Passed + Failed must equal the number of valid scores.
  5. Use the summary table, not raw rows, as the pie-chart source.

4. Version-history recovery

  1. Open File > Version history > See version history.
  2. Select the time before deletion.
  3. Use editor colors and the preview to verify the correct state.
  4. Restore only after considering valid later edits.
  5. Confirm the table and document the recovery.

5. PivotTable verification

  1. Manually total a small sample category.
  2. Create the PivotTable using Category in Rows and Sales in Values.
  3. Confirm the aggregation label is Sum of Sales.
  4. Compare the PivotTable category total with the manual sample.
  5. Filter South using the slicer and record the changed Grand Total.

6. C-R-T-O Study Assistant prompt

  1. Context: Semester-I student learning storage.
  2. Role: IT lab tutor.
  3. Task: Compare RAM, HDD and SSD, then ask one question.
  4. Output: 150 words, one table, no next topic until the learner answers.
  5. Verification: Check technical claims against the official text/reference.

Quick Revision

Final checklist before practical tests

One-look rules

  • CPU executes; RAM works; SSD/HDD stores.
  • Copy duplicates; Move relocates.
  • To acts; CC informs; BCC hides addresses.
  • Styles create consistent documents and TOCs.
  • COUNT numbers; COUNTA non-empty cells.
  • Refresh PivotTables after source changes.
  • Choose charts by relationship, not decoration.
  • AI output requires verification and privacy review.

Common failure points

  • Wrong file/folder destination.
  • Private addresses exposed in CC.
  • Text numbers causing PivotTable Count.
  • Formula ranges include headers or miss rows.
  • Version history restored without reviewing later edits.
  • Misleading chart axes or unnecessary 3D.
  • AI prices used without date/source.
  • Poster uses unlicensed image or unreadable contrast.

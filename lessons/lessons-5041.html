Course Overview

What this subject teaches

Embedded Systems explains how dedicated computer systems are built inside products. The course moves from general embedded architecture to AVR microcontrollers, embedded C programming, peripheral interfacing, serial buses and RTOS fundamentals.

Main purpose

Understand embedded-system blocks, select a microcontroller, program ATmega32 using embedded C, interface peripherals and explain RTOS basics.

Industrial value

Embedded controllers are used in lifts, escalators, drives, sensor modules, medical devices, meters, battery chargers, industrial indicators and automation equipment.

Drawing engineer value

This helps with controller I/O drawings, communication wiring, sensor interfaces, relay/motor driver circuits, board-to-board connections and troubleshooting documentation.

Blunt warning: Do not study this subject as only definitions. If you cannot explain sensor input, firmware decision, driver output and timing requirement in one flow, your embedded-system understanding is incomplete.
Study Method

How to study this handbook

Correct learning order

  1. Start with definition, purpose and classification of embedded systems.
  2. Understand hardware and firmware components separately.
  3. Study ATmega32 blocks, memory, ports, registers, timers and interrupts.
  4. Practise embedded C logic for I/O, delay, timers and interrupts.
  5. Study peripheral interfacing: LED, relay, sensors, display, motors, RTC and ADC.
  6. Understand I2C and SPI as on-board communication interfaces.
  7. Finish with RTOS kernel, tasks, scheduling and synchronization.

Exam answer method

  1. Start with definition and application context.
  2. Draw block diagram or interface diagram.
  3. Explain hardware blocks and firmware sequence.
  4. For programming questions, write algorithm/pseudocode and key register logic.
  5. For RTOS questions, write task, scheduler, communication and synchronization points.
  6. End with practical applications.

CO1 • Embedded Basics • Architecture

Module 1 - Basics of Embedded Systems and Architecture

Definition, classification, components, architecture, memory, sensors, actuators and interfaces. Total syllabus load: 13 hours.

Core idea

An embedded system is a special-purpose computer built into a product to perform a dedicated task. It combines hardware and software, usually with strict cost, size, power, timing and reliability limits.

Embedded system ഒരു dedicated task ചെയ്യാൻ product-ന്റെ ഉള്ളിൽ embedded ആയ computer system ആണ്. General computer പോലെ all-purpose അല്ല; specific control/function ആണ് main.

Embedded system vs general computer

Embedded system performs a dedicated function inside a product; general computer is flexible and user-programmable for many tasks.

Classification

Embedded systems may be stand-alone, real-time, networked or mobile. They may be small, medium or sophisticated based on complexity.

Hardware components

Core processor, memory, power supply, clock, reset circuit, sensors, actuators, I/O devices, drivers and communication interfaces.

Software components

Firmware, device drivers, interrupt routines, communication routines, scheduler/RTOS if required and application logic.

Sensors and actuators

Sensors convert physical quantities to electrical signals. Actuators convert electrical control signals into physical action.

Interfaces

On-board interfaces include I2C, SPI and UART. External interfaces include RS232, USB, Bluetooth and Wi-Fi.

CO2 • AVR • ATmega32 • Embedded C

Module 2 - AVR Microcontroller and Embedded C Programming

ATmega32 architecture, registers, memory, ports, timers, interrupts and embedded C program development. Total: 16 hours + 1 series test.

Core idea

AVR microcontrollers are RISC-based controllers suitable for embedded products. ATmega32 includes Flash memory, SRAM, EEPROM, I/O ports, timers, ADC, serial interfaces and interrupt support.

ATmega32 embedded C programming-ൽ DDRx, PORTx, PINx registers, timers, interrupts എന്നിവ practical ആയി use ചെയ്യുന്നു. Port direction set ചെയ്യാത്തത് common mistake ആണ്.

AVR family selection

Select based on Flash size, RAM, EEPROM, I/O pins, ADC channels, timers, communication interfaces, speed, package and cost.

ATmega32 blocks

CPU core, Flash, SRAM, EEPROM, I/O ports, timers, ADC, USART, SPI, interrupt controller, oscillator and reset unit.

Registers and memory

AVR has general-purpose registers, status register, program counter, program Flash, data SRAM, I/O memory and special function registers.

I/O programming

DDRx sets direction, PORTx writes output or enables pull-up, and PINx reads input level.

Timers

Timer0, Timer1 and Timer2 generate delays, PWM and timing events. Prescaler divides clock for required timing range.

Interrupts

Interrupts execute service routines for external pins, timers and communication events. Correct enabling and flag handling is essential.

CO3 • Interfacing • I2C • SPI

Module 3 - AVR Peripheral Interfacing

Interface LED, push button, relay, optocoupler, sensors, displays, motors, RTC, ADC, I2C and SPI. Total: 19 hours.

Core idea

Interfacing converts microcontroller pins into useful real-world action. Good interfacing needs correct voltage level, current capability, protection, timing and communication protocol handling.

AVR pin direct ആയി high-current load drive ചെയ്യരുത്. Relay/motor/stepper use ചെയ്യുമ്പോൾ driver, flyback protection, common ground, supply rating എന്നിവ check ചെയ്യണം.

LED and push button

LED requires current-limiting resistor. Button input needs pull-up or pull-down and software debouncing.

Relay and optocoupler

Relay switches higher power loads. Optocoupler provides electrical isolation between control and power sections.

Sensors and ADC

Temperature and IR sensors produce analog or digital signals. ADC converts analog level into digital value.

Seven segment and LCD

Seven segment displays numeric values. LCD displays text and status using control/data lines.

Motors

DC motor uses driver and PWM speed control. Servo uses pulse width control. Stepper uses sequence control through driver.

RTC, I2C and SPI

RTC keeps time, commonly through I2C. SPI is a high-speed synchronous serial bus using master, slave select, clock and data lines.

Interfacing checklist

  • Confirm supply voltage and current rating.
  • Use driver stage for relay, motor and buzzer.
  • Use protection diode for inductive loads.
  • Use current-limiting resistor for LED.
  • Keep common ground where non-isolated modules are used.
  • Check pull-up resistors for I2C and switch inputs.
  • Debounce mechanical switches in firmware.

CO4 • RTOS • Kernel • Scheduling

Module 4 - Real Time Operating Systems

Kernel, OS architecture, RTOS functions, selection criteria, Micro C/OS-II and popular RTOS. Total: 10 hours + 1 series test.

Core idea

An RTOS manages multiple time-critical tasks in embedded systems. It provides predictable scheduling, task communication, synchronization, timing services and device-driver support.

RTOS use ചെയ്യുന്നത് multiple tasks predictable time-ൽ run ചെയ്യേണ്ടപ്പോൾ ആണ്. Simple single-loop program മതിയെങ്കിൽ RTOS unnecessary complexity ആകും.

Kernel

Kernel is the core part of the operating system. It manages CPU time, tasks, memory, interrupts and system services.

GPOS vs RTOS

GPOS focuses on average performance and user features. RTOS focuses on deterministic response within timing limits.

Tasks, process and threads

A task is an independent unit of execution. A thread is a lightweight execution path. A process owns resources and execution context.

Scheduling

Scheduling decides which task runs next. RTOS scheduling may be priority-based, preemptive or time-sliced.

Communication and synchronization

Queues, mailboxes, semaphores, mutexes and event flags coordinate tasks and share data safely.

Micro C/OS-II

Micro C/OS-II is a real-time kernel offering task management, scheduling, time management, semaphores, mailboxes and queues.

Timing, ADC and interface formulas

Timer basics

Timer tick period = Prescaler / CPU clock frequency
Overflow time = Timer resolution count × tick period
Required counts = Delay / tick period

ADC

ADC step size = Vref / 2^n
Analog voltage = ADC count × step size
For 10-bit ADC, total levels = 1024

Interface memory points

I2C uses SDA and SCL with pull-up resistors
SPI uses MOSI, MISO, SCK and SS
PWM duty cycle = ON time / total period

Answer Key

Complete model answers - condensed exam format

1. Embedded system

An embedded system is a dedicated computer system built into a product to perform a specific function using hardware and firmware.

2. Difference from general computer

Embedded system is task-specific, resource-limited and product-integrated. General computer is user-programmable for multiple purposes and has larger resources.

3. Hardware components

Processor, memory, clock, reset circuit, power supply, sensors, actuators, I/O devices, drivers and communication interfaces.

4. Sensor and actuator

Sensor converts physical quantity into electrical signal. Actuator converts electrical control signal into physical action.

5. AVR selection criteria

Flash size, RAM, EEPROM, number of I/O pins, ADC channels, timers, serial interfaces, speed, package, power and cost.

6. DDRx, PORTx and PINx

DDRx configures direction, PORTx writes output or enables pull-up and PINx reads input level.

7. Need for interfacing

Interfacing adapts voltage, current, timing and signal format between microcontroller and external device.

8. I2C

I2C is a two-wire synchronous serial bus using SDA data line and SCL clock line.

9. RTOS

RTOS is an operating system designed to provide deterministic response for time-critical tasks.

10. Popular RTOS examples

FreeRTOS, VxWorks, QNX, RTLinux, ThreadX, Nucleus, Zephyr, embOS, Micro C/OS-II and Integrity.

11. Classification

Embedded systems may be stand-alone, real-time, networked or mobile. They may also be small, medium or complex based on hardware/software complexity.

12. Building blocks

Blocks include core processor, memory, sensors, actuators, input/output, power supply, clock, reset, communication interface and firmware.

13. ATmega32 block diagram

ATmega32 contains AVR CPU, Flash memory, SRAM, EEPROM, I/O ports, timers, ADC, USART, SPI, interrupt controller, oscillator and reset circuit.

14. Memory and status register

AVR memory includes program Flash, data SRAM, EEPROM and I/O memory. Status register stores flags such as carry, zero, negative, overflow and global interrupt enable.

15. Embedded C I/O and delay

Set port direction using DDRx, write output using PORTx, read input using PINx. Delay can be created using software loop or timer count based on clock and prescaler.

16. Basic interfacing

LED needs current-limiting resistor. Push button needs pull-up/pull-down and debounce. Relay requires driver and protection. Optocoupler provides isolation.

17. I2C vs SPI

I2C uses two lines and device addressing, suitable for RTC/sensors. SPI uses MOSI, MISO, SCK and slave select, usually faster but needs more lines.

18. RTOS kernel functions

Kernel manages tasks, scheduling, time delays, interrupt handling, communication, synchronization and device services.

19. Architecture answer

Embedded architecture combines core processor, memory, sensor inputs, actuator outputs, I/O subsystem, communication interface, firmware and power/clock/reset circuits.

20. AVR answer

Select AVR based on resources and interfaces. ATmega32 provides CPU, memory, I/O ports, timers, ADC, serial interfaces and interrupts for embedded applications.

21. Embedded C answer

Embedded C programs configure registers, set I/O direction, process inputs, perform logic/conversion, generate delays using loops or timers and handle interrupts through service routines.

22. Peripheral interfacing

Displays, sensors, keyboard and motors are connected using proper I/O lines, drivers, protection and timing. DC motor uses PWM, servo uses pulse width and stepper uses sequence control.

23. RTC, ADC, I2C and SPI

RTC commonly communicates through I2C. ADC converts analog signals into digital values. SPI uses separate data and clock lines for high-speed synchronous communication.

24. RTOS answer

RTOS provides deterministic task scheduling, task communication, synchronization, device drivers and timing services. Selection depends on response time, memory use, device support, reliability and cost.

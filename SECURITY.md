# 🔒 Security Policy

Thank you for helping keep **POLY PMNA** secure.

This document explains which versions are supported and how to responsibly report security vulnerabilities.

---

# Supported Versions

The following versions currently receive security updates.

| Version | Supported |
|---------|:---------:|
| Latest (main branch) | ✅ |
| Previous stable release | ✅ |
| Older releases | ❌ |

> Security fixes are applied only to the latest maintained version of the project.

---

# Scope

This policy applies to the following components:

- POLY PMNA Website
- Revision 2026 Portal
- Revision 2021 Portal
- Ask Poly AI
- Daily Quiz
- Engineering Tools
- Cloudflare Workers
- Supabase Backend
- GitHub Actions Workflows

---

# Reporting a Vulnerability

If you discover a security vulnerability, **please do not create a public GitHub Issue**.

Instead, report it privately by one of the following methods:

- GitHub Private Security Advisory (recommended)
- Contact the project maintainer directly

Include the following information:

- Description of the vulnerability
- Steps to reproduce
- Affected URL or file
- Browser or device used
- Screenshots (if applicable)
- Potential impact
- Suggested mitigation (optional)

---

# Response Process

After receiving a report:

- We will acknowledge receipt as soon as reasonably possible.
- The issue will be investigated.
- If confirmed, a fix will be developed and tested.
- Security updates will be released in the next appropriate update.
- Reporters may be credited for responsible disclosure if they wish.

---

# Responsible Disclosure

Please do not publicly disclose security vulnerabilities until a fix has been released.

Responsible disclosure helps protect all users of POLY PMNA.

---

# Security Practices

The project follows these practices where applicable:

- HTTPS for all production services
- Secure authentication
- Environment variables for secrets
- Server-side validation for sensitive operations
- Regular dependency updates
- Input validation
- Secure database access
- Least-privilege access control

---

# What Should Be Reported?

Examples include:

- Authentication bypass
- Unauthorized data access
- SQL Injection
- Cross-Site Scripting (XSS)
- Cross-Site Request Forgery (CSRF)
- Remote Code Execution
- API vulnerabilities
- Supabase security issues
- Cloudflare Worker vulnerabilities
- Sensitive information exposure

---

# Out of Scope

The following are generally not considered security vulnerabilities:

- Typographical errors
- UI or styling issues
- Browser compatibility problems
- Feature requests
- Missing documentation
- Performance improvements
- Educational content errors

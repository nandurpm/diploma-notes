# Ask POLY Streaming and Grounding-QA Fix Report

Date: 2026-08-22

## Streaming test

The deployed client previously used a 24 ms delay between display tokens. Because the client groups provider chunks into complete words, this is approximately 42 words per second after provider data arrives. The live timing test showed the progressive response bubble and the `POLY is writing…` state while an answer was arriving. The fallback path was also observed when the live AI relay was unavailable.

The display pace was adjusted to 32 ms between words, approximately 31 words per second, which is easier to follow while remaining responsive. The cursor was changed from the heavy `▋` glyph to a thinner `▌`, with a 720 ms blink cycle, reduced font weight, and existing reduced-motion support retained.

## Grounding-QA diagnosis

The failed CI QA run was not caused by a production page failure. The test launched the page from `http://127.0.0.1:8000` while the browser executed real health and request calls against production endpoints. The API endpoints were not intercepted because the route stub matched only the exact URL without the client-added cache-busting query string. The Supabase fallback route was also absent, and the health stub targeted an obsolete Workers endpoint.

The QA script now intercepts the current protected API, health endpoint, and Supabase relay/fallback endpoints with optional query strings. It returns QA-only JSON stubs, so the test no longer performs cross-origin calls during local CI rendering. The corrected suite passed all checks: page load, knowledge index, 42 Revision 2026 programmes, desktop overflow, request context, mobile overflow, mobile saved-chat panel, and zero console errors.

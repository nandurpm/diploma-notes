## 2026-07-17 - Client-Side Search Event Listeners Lack Debouncing
**Learning:** In static, multi-page client-side architectures, distinct pages or department scripts often implement their own search and rendering logic. Although some core search utilities (like `subject-browser.js`) utilized `setTimeout`-based debouncing to throttle DOM re-renders, several other page-specific browser scripts (`sitttr-rev2021-browser.js`, `revision-2026-browser.js`, `department-subject-alias-hotfix.js`, etc.) listened to raw `input` events and executed synchronous DOM reflows and string matches on every single keystroke. This causes severe input lag and high CPU spikes, particularly on lower-end mobile devices and for large subject collections.
**Action:** When working on performance optimization for static web apps, search all instances of `.addEventListener("input"` across the entire codebase to identify unthrottled DOM rendering hooks and consistently apply a lightweight `setTimeout` debouncer pattern.
